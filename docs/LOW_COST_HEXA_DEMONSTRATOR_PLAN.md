## 仿真架构草案 v0.1

本节定义拟实现的独立离线演示，不表示已有仿真程序或测试通过。
保留六足仿生主线；不从 G1 删除腿部，不修改 G1.5–G4 的现有合同或门控。
首版对象是中心机体、六个机臂、六个动力单元和飞控占位；不加入下肢与任务舱。
600 元为未来实物总支出约束，仿真尺寸和材料参数仍须标明假设。

### 模块与两条链路

- 几何模块：描述中心机体、飞控安装区、六个电机中心和桨盘占位，尺寸参数化。
- 指令模块：产生带序号、仿真时间戳、模式和六路值的离线测试输入。
- 控制接口模块：检查六路映射、输入范围、有效期和停止状态；输出仅写入离线记录。
- 模拟执行模块：显示六路命令及状态，不将命令值冒充真实转速、推力或电流。
- 姿态数据模块：第一版只读取有来源标记的合成轨迹，验证显示和坐标转换。
- 记录模块：保存场景参数、输入、输出、事件和判定；结果标记 SIMULATED / ANALYSIS_ONLY。

未来实物的信号链是“电脑/飞控接口 → 六路电调控制输入 → 六个电机”。
供电链是“适配电源 → 配电 → 六路电调/电机”，飞控另按实际板型接入适配供电。
信号线和供电线在图与接口表中分别描述；USB 连接不被假定为六个电机的动力电源。
这里没有确定电压、电流、连接器或具体接线，须待器件选定后核实。

### 坐标与编号约定

独立演示机体系拟定为 x 向前、y 向左、z 向上；角度采用弧度，长度采用米。
几何槽位命名 R1–R6，俯视从前左槽位起按逆时针顺序排列。
对称布局的初始参数角为 30、90、150、210、270、330 度，距中心均为 r。
位置由 x = r*cos(theta)、y = r*sin(theta)、z = h 定义；r、h 为待定几何参数。
旋转方向暂按 R1 逆时针、R2 顺时针交替设置，观察方向为从机体上方向下看。
这些是本演示的内部约定，不是任何现成飞控的电机编号或固件旋向要求。
后续用显式映射绑定“几何槽位 → 模拟通道 → 固件电机号 → 实际输出”，禁止按编号直接猜接线。
对外固件坐标系如不同，须定义并测试转换；不直接复用本约定作为飞控配置。

### 桌面单通道离线接口与状态

拟定输入包含 schema_version、sequence、sim_time_s、mode、motor_command[6]。
motor_command 为无量纲 0–1 演示值，不对应已校准的 PWM、DShot 或推力。
第一版 mode 仅有 IDLE、CHANNEL_TEST、STOP；CHANNEL_TEST 每次最多一路非零。
启动进入 IDLE，输出全零；合法显式测试输入才能进入 CHANNEL_TEST。
STOP、非法输入、非有限数、乱序、过期或模拟断链均令六路输出归零并记录原因。
STOP 和故障保持锁存，显式复位后回到 IDLE，不能自动恢复此前非零命令。
过期阈值作为场景参数，在实现前给出固定测试值；它不是实物停止时间指标。
结果分别记录 requested_command、accepted_command、state 和 rejection_reason。
此接口不连接串口、网络飞控或真实执行器，也不绕过任何现成飞控的检查。
该状态机仅用于桌面单通道测试，不能复用为飞行模式或空中失联策略。
飞行闭环需要六路同时分配；空中失联、低电量和传感器故障的处理须按飞行状态单独设计，
不能把桌面测试的“异常即六路归零”推广为飞行中应对所有故障的方式。

### 仿真层级与证据边界

第一层是几何与可视化：验证位置、坐标轴、编号、参数变化及装配空间占位。
第二层是离线信号行为：验证六路一一对应、输入检查、停止、复位及日志重放。
两层均不能证明姿态稳定；合成姿态播放必须在界面和记录中明确标记。
第三层是必须完成设计与验证的闭环动力学：控制器、执行器、刚体运动和传感器构成反馈环。
第三层实施前需明确质量/惯量、推力/反扭矩、延迟、噪声、步长及参数证据，
另定可量化响应指标；缺失这些参数时不声称悬停、抗扰或飞行性能得到验证。
模型范围包含机载电池与整机质量、重心和惯量、六路推力及控制分配、执行器限幅、
姿态估计与控制、起飞/悬停/降落状态以及控制链路。参数来源与不确定性必须可追踪。
质量、推力裕量、供电能力及成本必须一起核算，不能以桌面能转动证明能起飞。

## 离线仿真验收草案

以下全部为待实现、待运行项目；不与上文未来实物验收混用。

- SIM-01 几何：恰有六个唯一槽位，无下肢；给定 r、h 时各槽位坐标与公式一致。
  检查桨盘及机体占位间距，记录所用尺寸；占位几何通过不证明结构强度。
- SIM-02 映射：六个单通道场景逐一运行，目标槽位唯一响应，其余五路为零；拒绝重复或缺失映射。
- SIM-03 输入：覆盖错误长度、负值、超过 1、NaN/Inf、乱序和过期输入；均记录拒绝并归零。
- SIM-04 停止：非零测试中注入 STOP 或断链，下一次离线状态更新输出归零；恢复输入后仍保持锁存。
  复位只返回 IDLE，重新显式开始测试才允许非零；不推导实物刹停距离或时间。
- SIM-05 姿态：用已知零姿态与单轴正负旋转轨迹检查轴向和单位；所有画面标注合成数据。
- SIM-06 重放：相同配置和输入得到相同输出及事件顺序；记录版本、场景和假设，便于复现。
- SIM-07 边界：无真实执行器输出，报告保留 ANALYSIS_ONLY 和 procurement_allowed=false；
  缺失参数写 UNKNOWN，未运行项目写 NOT_RUN，不把未实现的闭环或实物能力标为 PASS。
- FLIGHT-SIM-01 模型：明确质量、惯量、动力与电池参数来源和不确定性；缺失项不得用无标记默认值补齐。
- FLIGHT-SIM-02 闭环：在规定场景模拟受控起飞、悬停及降落，记录姿态/高度误差、执行器饱和与供电需求。
  高度、时长和误差阈值须在测试前定义，未定义则不判通过。
- FLIGHT-SIM-03 扰动与故障：检查参数偏差、外界扰动及链路/传感器异常的状态处理，区别空中与地面行为。
- FLIGHT-SIM-04 证据：记录模型版本、控制器版本、场景及定量结果；仿真通过仍不等于实物起飞通过。

实施顺序：先完成坐标/映射和桌面离线状态测试，再推进独立闭环仿真及其可视化；闭环是目标路线的必需环节。
可视化是展示入口，测试记录是正确性证据；首版交付应同时包含二者。

## 随项目推进的硬件学习任务

1. 对照模块图，用自己的话解释飞控、电调、电机、供电和电脑各自负责什么，并区分信号与供电。
2. 对照六路模型，指出前后左右、六个槽位、旋向和控制通道，解释编号为何需要映射。
3. 对照故障场景，解释上电不启动、停止锁存和失联处理；区分命令归零与电机实际停转。
4. 选型恢复前，学会读额定电压、电流、接口和供电要求，理解短路、极性、通断检查及焊接基础。
5. 实物装配前，再把具体器件资料转为接线图与逐步检查表，完成工具使用练习。
6. 随闭环设计学习质量与推力、重心/惯量、姿态反馈、六路控制分配、电池供电和飞行状态处理。

按项目进度教学，保留当前先仿真、不采购的边界，桌面测试只是学习与研发中的中间步骤。

学习产出以能解释当前设计、识别接线错误和读懂测试结果为准，不设必须先学完整门硬件课程的前提。
